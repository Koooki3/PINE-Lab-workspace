# openpi 完整中文讲解：从数据到模型，再到推理部署

## 0. 一句话认识 openpi

openpi 是 Physical Intelligence 发布的机器人基础策略代码库。它把“摄像头看到了什么、用户说了什么、机器人现在是什么姿态”变成“一段接下来要执行的动作”。仓库不是机器人操作系统，也不替你提供驱动、标定、碰撞检测和急停；它处在感知输入与底层控制器之间的学习策略层。[L1][P1]

## 1. 最小心智模型

把机器人想成一位需要连续做决定的学徒：

1. 相机图像告诉它环境；语言提示告诉它任务；本体状态告诉它手臂当前在哪里。
2. 数据适配器把不同机器人五花八门的字段整理为模型统一接口。
3. VLM 提取“图像里有什么、任务要做什么”的语义。
4. 动作专家根据语义和当前状态生成未来一小段动作，即动作块。
5. Policy 封装负责与训练时完全一致的归一化、tokenization、推理和反归一化。
6. 本机或远程服务器把动作块传给机器人控制循环，循环执行一部分后重新观察并规划。

关键边界：VLA 输出通常是关节位置、末端位姿增量或夹爪指令等高层连续量，不等于电机电流。真机仍需要频率匹配、坐标系约定、限幅和安全控制器。

## 3. 数据层：模型真正吃什么

### 3.1 一个训练样本

统一后的样本可以理解为：多路 RGB 图像、图像有效掩码、机器人状态、语言提示以及未来动作序列。π0 默认模型规格包含三路图像槽位，图像被整理到固定分辨率；状态和动作最后一维填充到 `action_dim=32`；动作块默认长度为 `action_horizon=50`。[L3][L4]

“32 维”是统一容器而非宣称每台机器人都有 32 个自由度。实际平台只使用其中与自己本体对应的维度，其余填充；输出时再裁剪回真实动作维数。

### 3.2 两条数据入口

- LeRobot：默认路径。`LeRobotDataset` 根据数据集帧率构造未来 50 步的时间偏移，适合 LIBERO、ALOHA 以及自建数据。[L3]
- RLDS：当前代码专门服务 DROID。它是独立的可迭代批数据管线；可选依赖组锁定 TensorFlow CPU 2.15，而该 wheel 只支持 Python 3.11。[L2][L3]

### 3.3 变换链

数据不是读出来就直接喂模型，而是依次经过：

1. `repack_transforms`：把原始数据键映射到策略期望的键。
2. `data_transforms`：做平台语义变换，例如绝对/相对动作、关节与末端位姿组合。
3. `Normalize`：使用预先计算的均值/方差或分位数统计量缩放状态与动作。
4. `model_transforms`：resize 图像、tokenize 提示、pad 状态/动作、构造模型对象。

输出方向按相反顺序执行。最常见且危险的错误不是网络结构，而是训练和部署使用了不同坐标系、动作符号、维度顺序或统计量。

### 3.4 自有数据接入清单

- 明确观测时间戳、控制频率、相机同步方式与动作含义。
- 统一 RGB 通道、图像方向和相机名称；缺失相机用 mask 标记。
- 明确状态是关节角、末端位姿还是混合量，旋转表示要固定。
- 明确动作是绝对目标还是增量，夹爪开合范围及正负方向要一致。
- 切分训练/验证时按 episode 或场景切分，避免相邻帧泄漏。
- 转成 LeRobot 后抽查 episode 边界和 50 步动作窗口，再计算 norm stats。

## 4. 模型层

### 4.1 π0：VLM 加动作专家

π0 的前缀由多路图像 token 和语言 token 组成。视觉部分采用 SigLIP 编码器，语言/多模态骨干使用 Gemma/PaliGemma 风格模块；前缀内部可双向关注。动作后缀包含本体状态、带噪动作和时间条件，由较小的 Gemma 动作专家处理。[L4][P1]

训练时，真实动作与高斯噪声按随机时间插值得到带噪动作；目标是预测从真实动作指向噪声的速度场。损失是预测速度与目标速度的均方误差。推理从高斯噪声出发，默认用 10 个 Euler 步沿反方向积分到动作样本；视觉语言前缀的 KV cache 只计算一次，因此每个去噪步主要重算动作后缀。[L4]

这和“逐个 token 生成关节值”不同：流匹配天然处理连续、多峰、相关的整段动作。

### 4.2 π0.5：更强的开放世界泛化目标

π0.5 延续 π0，但论文强调把多机器人数据、网页语义知识、高层子任务预测和低层动作共同训练，以改善新家庭、新物体和长时程任务泛化。[W4][W5]

当前源码中的可见差异包括：状态被编码进离散语言 token，而不是作为单独连续后缀 token；流时间通过 adaptive RMSNorm 条件注入动作专家；提示最大长度从 π0 默认 48 增加到 200。[L4] 仓库当前只支持 π0.5 的 flow-matching head，不能把论文所有训练配方等同于开源实现。[L1]

### 4.3 π0-FAST：动作也变成 token

FAST 先用频域变换和量化把连续动作序列压成离散 token，再由自回归模型像生成文本一样生成动作 token，最后解码回连续动作。[L5][W6] 优点是可复用语言模型式的离散序列训练；代价是量化、码本与自回归延迟。当前 PyTorch 实现不支持 π0-FAST，应使用 JAX 路径。[L1]

### 4.4 三者怎么选

- 第一次在新数据上微调：优先官方 README 当前主推的 π0.5 flow 配置。
- 需要更快的连续动作推理且语言服从不是首要：可比较 π0 flow 的平台检查点。
- 研究统一 token 序列或 DROID FAST 配方：选择 π0-FAST，但接受 JAX-only 限制。
- 只有 8 GB 显存：先做客户端、数据和 CPU fake-data 验证；官方推理需求是严格大于 8 GB，不应把本机 8 GB 视为满足。

## 5. 训练层

标准流程是：数据转换 → 定义平台输入/输出适配 → 定义 `DataConfig` 和 `TrainConfig` → 计算 norm stats → 加载基础检查点 → 微调 → 保存检查点与元数据。[L1][L8]

JAX 是功能最完整的原生实现，可做 LoRA 与设备分片；PyTorch 支持 π0/π0.5 推理和微调并在 LIBERO 验证过，但 README 明列不支持 π0-FAST、混合精度、FSDP 与 LoRA。[L1]

显存估算以官方当前 README 为准：推理大于 8 GB、LoRA 微调大于 22.5 GB、全量微调大于 70 GB。它们是粗略下界，分辨率、batch、编译缓存与驱动都会改变峰值。[L1]

## 6. 推理层：一次 `infer` 发生什么

1. 平台适配器把机器人字典转换为统一字段。
2. 输入变换做图像处理、归一化和提示 tokenization。
3. 模型生成一个动作块。
4. 输出变换反归一化并恢复平台动作格式。
5. Policy 返回动作以及可选运行统计。

检查点不只是权重。可复现推理至少需要与权重匹配的训练配置、模型类型、tokenizer、norm stats、输入/输出变换和平台字段约定。[L6]

## 7. 部署层

### 7.1 同机部署

机器人进程直接加载完整 Policy。路径短但会把 CUDA/JAX/PyTorch 依赖、GPU 资源和机器人驱动耦合到同一环境，调试和故障隔离较困难。

### 7.2 远程策略服务

推荐把完整模型放在 GPU 服务器，运行 `scripts/serve_policy.py`；机器人侧只安装 `openpi-client`，用 WebSocket 和 msgpack-numpy 发送观测、接收动作。服务端提供 `/healthz`，响应包含推理耗时元数据。[L7]

远程部署要额外处理：网络抖动、超时、观测序号、过期动作丢弃、断线安全姿态、带宽、认证和加密。仓库示例协议本身不等同于生产安全网关。

### 7.3 闭环执行

动作块不必全部开环执行。常见做法是只执行前若干步，然后用新观测重新推理；执行越短反馈越及时，但推理和网络压力越大。应根据控制频率、推理延迟和任务动力学选择执行窗口，并记录端到端延迟。

## 8. `kooki` 环境结论

仓库主 Python 环境约定为 Conda `kooki`。当前机器审计基线：Windows 11、Python 3.12.9、RTX 4060 Laptop 8 GB、NVIDIA driver 610.88。

不能把该环境标为 openpi “完整支持”：上游只测试 Ubuntu 22.04；JAX 依赖写为 `jax[cuda12]==0.5.3`，Windows 不是官方 CUDA JAX 运行路径；RLDS 的 TensorFlow 2.15 可选组要求 Python 3.11；8 GB 也未达到 README 的“>8 GB”推理门槛。[L1][L2]

本仓库的可执行策略是：

- `kooki` 保持日常主环境，用于源码阅读、数据转换、openpi-client、非 GPU 工具与可安装模块测试。
- 完整 JAX/CUDA 推理或训练使用 Ubuntu 22.04/WSL2 的 Python 3.11 `uv` 锁定环境。
- RLDS/DROID 单独使用 Python 3.11 环境，避免为兼容 TensorFlow 2.15 降级主环境。
- 不为“看起来装全了”而强行在 Windows 覆盖 JAX CUDA轮子；以导入、设备枚举和 fake batch 冒烟测试为验收。

## 9. 常见故障定位

| 症状 | 优先检查 |
| --- | --- |
| 动作方向反了或幅值异常 | 输入/输出适配、绝对/增量语义、norm stats、关节顺序 |
| 换场景后失效 | 相机视角、提示分布、训练覆盖、图像预处理 |
| 推理首帧很慢 | JAX/PyTorch 编译与权重下载缓存 |
| 服务端正常但机器人不动 | 消息字段、客户端裁剪、控制器频率、超时/急停状态 |
| OOM | 模型类型、显存、batch、精度、编译缓存；不要用 8 GB 卡硬顶官方门槛 |
| DROID/RLDS 安装冲突 | Python 3.11 与独立可选组，不要在 3.12 主环境强装 TensorFlow 2.15 |

## 10. 初学者的第一个可靠实验

先不接真机、不下载大检查点：验证 `openpi-client` 编解码和图像处理；用 fake dataset 验证配置产生的观测/动作形状；逐步打印变换前后字段；最后在官方支持的 Linux GPU 环境加载 LIBERO 检查点并通过 simple client 请求一次推理。只有这些都通过后，再接仿真和真机。

## 11. 术语表

- VLA：Vision-Language-Action，视觉和语言条件下生成动作的模型。
- embodiment：机器人本体及其传感器、自由度、坐标系和执行器约定。
- action chunk：一次预测的未来多步动作序列。
- flow matching：学习连续向量场，把噪声沿 ODE 变换为数据样本。
- norm stats：训练数据的归一化统计量，属于检查点语义的一部分。
- policy：把原始观测变成可执行动作的完整封装，不只是神经网络。
- checkpoint：权重及恢复推理所需的配置和资产集合。
